# evol-dermatoglyph

Pipeline for genomic data collection, quality assessment, phylogenetic inference, and evolutionary analysis of primate genomes and orthologs.

## Overview

This repository contains a set of scripts to:

1. download genome data from NCBI;
2. filter isoforms and prepare proteins of interest;
3. assess completeness and quality with BUSCO;
4. perform phylogenetic alignments;
5. infer trees with IQ-TREE;
6. estimate ultrametric trees and evolutionary trends with OrthoFinder, CAFE, and selective pressure analyses.

## Repository structure

- `01_data_collection.sh` — genome download pipeline
- `02_quality_assessment.sh` — isoform filtering and BUSCO evaluation
- `03_phylogenetic_inference.sh` — alignment, trimming, concatenation, and IQ-TREE
- `04_evolutionary_analyis.sh` — OrthoFinder, r8s, CAFE, and selection tests
- `data/` — metadata tables and input/output files

## Requirements

The pipelines depend on external bioinformatics tools, including:

- NCBI Datasets CLI
- AGAT
- BUSCO
- BLAST+
- MAFFT
- trimAl
- IQ-TREE
- OrthoFinder
- r8s / pyr8s
- CAFE
- GUIDANCE
- ETE3
- Python 3

Most steps require a bioinformatics environment with these tools installed and available in the `PATH`.

## Setup

1. Update the files in `data/table_acc-sp.tsv` and `data/species_folder.list` according to the project.
2. Verify that species names and accessions match the NCBI database.
3. Define an NCBI API key if needed:

```bash
export NCBI_API_KEY="your_key"
```

## Execution

### 1) Data collection

```bash
bash 01_data_collection.sh
```

### 2) Quality assessment

```bash
bash 02_quality_assessment.sh
```

### 3) Phylogenetic inference

```bash
bash 03_phylogenetic_inference.sh
```

### 4) Evolutionary analyses

```bash
bash 04_evolutionary_analyis.sh
```

## Important notes

- The scripts were revised to reduce common syntax and path errors.
- The project assumes that the `data/` directory and the input files already exist.
- Some steps are computationally intensive and may require a machine with multiple cores.
- Raw outputs generated during downloads and alignments can be large; on GitHub, it is recommended to store heavy outputs in external storage or LFS.
